## A note on scope, before the table

**The GPU content was deleted, not corrected.** K6 attacked "NPU1 + NPU2 + AMD GPU" as a
"2–3 backends" claim. The user's scope rule, received after round 1, is that **this project is
about NPUs only and GPUs were never in scope**; r1 invented the GPU backend to make "2–3
backends" true. So the disposition of K6 is not "fix the GPU claim" but "remove GPU from §1.2,
§5 M6, §6, §8 and the appendices, and replace it with the honest NPU statement": one lowering
path (`air-to-aie` → MLIR-AIE), two AIE generations (NPU1 = Phoenix/AIE2, NPU2 = Strix/AIE2P)
selected by a device flag, plus Versal device values that `air-to-aie` accepts (its `device=`
option **defaults** to `xcvc1902`) with end-to-end Versal support marked `[UNVERIFIED]`.
Non-AMD NPUs (Qualcomm Hexagon, Tenstorrent Tensix) are separate backend *builds*, not AIR
targets, and §1.2 now says so plainly because the pitch depends on it. Every remaining
occurrence of the string "GPU" in the document is either that scope statement, the dialect fact
that a `gpu_symmetric_heap` channel type exists and is out of scope, or the user's own phrase
"Triton for GPU".
